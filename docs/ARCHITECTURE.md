# Архитектура PoolNet

Статус: этапы M0–M10 завершены, M11 (исправления по аудиту
[2026-10-24](AUDIT-2026-10-24.md)) в работе. В проде один процесс — `hub`
(FastAPI). `pool` — отдельный движок, который публикует файлы в общий каталог;
сайт — страницы `web/site`, которые `hub` рендерит из живых данных со
статическими фолбэками.

## Слои

- `hub/src/hub/api.py` — ядро FastAPI: подписки `/sub/*`, admin, Telegram-bot
  API, health/metrics, legacy-страницы `/design`, `/mockup` и собственный
  лендинг/статус для установки без сайта. Платформенных маршрутов здесь нет.
- `hub/src/hub/gateway.py` — слой платформенных маршрутов: отдача
  `web/site`, `/status`, `/api/status.json`, `/pool/*`, `/api/check`,
  редирект `/data/*`, 404. Регистрируется последним, поэтому ядро всегда
  выигрывает у его catch-all. Здесь же лимиты живой проверки.
- `hub/src/hub/poolstatus.py` — чистая агрегация: секции `vpn`/`pool` и
  render-модель сайта без FastAPI, сети и записи. Кэш `SiteDataSource`
  инвалидируется по mtime опубликованных файлов и текущей генерации.
- `hub/src/hub/siteview.py` — серверный рендер сайта без шаблонизатора:
  токены `{{path|fallback}}`, блоки `<!--begin:name-->…<!--end:name-->`,
  кэш по mtime файла и версии данных, HTML-экранирование. При отсутствии
  данных возвращает статический фолбэк страницы.
- `web/site` — разметка, CSS, шрифты и `flags.js`; английское дерево
  `web/site/en` повторяет те же страницы и токены. Страницы остаются валидным
  standalone HTML: в токенах лежат снимки чисел, в блоках — старые строки
  (таблицы, карта, воронка), которые заменяются живыми данными при рендере.
- `pool/src` — TypeScript-движок: источники → дедупликация → проверка
  реальными соединениями → обогащение → публикация в `pool/data`.
- `deploy/` — systemd-юниты (`poolnet.service`, `poolnet-pool.timer`) и
  шаблоны nginx (TLS-vhost, лимиты подписок, redacted-логи, потоковая
  отдача `/pool/*`, редиректы старых сервисов).
- `Makefile` и `.github/workflows/` — единые гейты: `make check` локально,
  те же шаги в CI (ruff 0.6.9 пинован, иначе новые правила краснят базу).

## Поток данных

```
pool engine (fetch → validate → merge → publish)
   └─ pool/data/{all,http,socks4,socks5}.txt
      pool/data/{proxies,meta,stats,benchmark,history}.json
      pool/data/country/XX.txt
            │
            ├─ hub GET /pool/*            (allow-list, файлы как есть)
            └─ hub /api/status.json       (секция pool из meta/stats/benchmark)
                                             │
hub store (SQLite: nodes, publishes, generations)
   └─ /api/v1/stats ────────────────────────┤ (секция vpn, тот же builder)
                                             ▼
                              render-модель gateway (M6)
                                             │
                              siteview: токены + блоки
                                             ▼
                                   web/site/*.html
```

VPN-поток идёт из хранилища `hub`: `/api/v1/stats` и секция `vpn` в
`/api/status.json` собираются одной функцией, поэтому не расходятся. Поток
прокси-базы не читает SQLite и не парсит многомегабайтные списки: статусу
достаточно агрегатов, а сами файлы отдаются отдельным маршрутом.

`gateway` строит render-модель через `poolstatus.site_payload` и отдаёт
страницы через `siteview`. Если каталога публикации нет или JSON битый,
токены остаются со статическими значениями, блоки — со старыми строками:
страница никогда не отвечает 500 из-за данных.

## Контракты

### `GET /api/status.json`

```json
{
  "vpn": { "generation": "…", "verified": 150, "known": 997,
           "by_protocol": {}, "by_country": [], "by_score": {},
           "published": [], "funnel": {} },
  "pool": { "available": true, "total": 30576, "grades": {},
            "median_ms": 127, "p95_ms": 5671, "cycle": {},
            "sources": 202, "countries_top": [], "benchmark_top": [] }
}
```

`vpn` побайтно совпадает с `/api/v1/stats`. `pool` читает только
`meta.json`, `stats.json` и `benchmark.json` из `POOLNET_POOL_DIR`; при
отсутствии каталога или всех трёх файлов возвращается
`{"available": false}`. Отсутствующий или битый JSON — не ошибка запроса:
значение просто не попадает в ответ.

### `GET /pool/*`

Закрытый allow-list: `http.txt`, `socks4.txt`, `socks5.txt`, `all.txt`,
`proxies.json`, `meta.json`, `stats.json` и `country/XX.txt` (ровно две
заглавные буквы). Всё остальное — 404. Файлы отдаются потоком с
`Cache-Control: max-age=60`. Старые адреса `/data/*` отвечают 307 на
`/pool/*`.

### `GET /api/check`

`proxy=host:port&proto=http|socks4|socks5`. Принимается только точечный IPv4
(без имён), порт 1–65535. Приватные, служебные и multicast-диапазоны
отклоняются до открытия сокета — эндпоинт нельзя превратить в пробу
внутренней сети. Проверка делает один полный запрос через туннель к
эхо-цели, отвечает `alive`, `remote_ip`, `latency_ms`, `error` и всегда
`Cache-Control: no-store`; таймаут — 8 секунд.

Частота ограничена на двух уровнях: token bucket 5 запросов в минуту на
подсеть (/24 для IPv4, /64 для IPv6) при burst 3 и общий потолок 8
одновременных проб. Превышение лимита — 429, занятые слоты — 503, оба с
`Retry-After: 60`. `/sub/*` дополнительно лимитируется nginx и приложением.

### Бесплатные ключи и админка

- `POST /api/free-subscription` выдаёт ключ на 7 дней без аккаунта и Telegram
  (`source=web`, `Cache-Control: no-store`). Лимит — 5 ключей в час на /24
  при burst 3; ответ 429. Токен сразу виден в админке со сроком и источником.
- `GET /admin` — панель оператора на том же домене; вход по `HUB_BOT_SECRET`.
  Лимит входа — 5 попыток за 15 минут. Необязательный `HUB_ADMIN_IPS`
  (список адресов через запятую) ограничивает доступ: остальным — 404.
- В панели: дашборд подписок, сроки/источник/последнее обращение, выдача,
  продление (`/admin/keys/extend`) и отзыв по 12-символьному префиксу.
  Платного тарифа и Premium-страницы нет.

### Шаблон страниц

- Токен: `{{dotted.path}}` или `{{dotted.path|статический фолбэк}}`.
  Отсутствующее значение → фолбэк, иначе `—`; значения экранируются.
- Блок: `<!--begin:name-->старое содержимое<!--end:name-->`. Поддержаны
  `rows:proxy`, `rows:sources`, `rows:protocols`, `rows:funnel`, `map:dots`.
  Пустые данные оставляют старый блок; неизвестный блок не трогается.
- Страницы без данных остаются валидными: числа в токенах — снимок
  последнего прогона, блоки — статические строки.

## Отказы

- Нет каталога пула или JSON-файлов → `pool.available: false`, страница
  сохраняет статические числа и не показывает пустую секцию.
- Битый или частично записанный JSON → чтение возвращает `None`, запрос не
  падает; при следующем цикле файл перезаписывается.
- Нет файла страницы или данных для `siteview` → `None`/фолбэк, без
  исключения; неизвестные токены не остаются в разметке.
- `/api/check` на приватный адрес → 400 до сокета; мёртвый прокси → вердикт
  `alive: false` с ошибкой, а не 500.
- Нет поколения подписок → 503 на `/sub/*`; горячий путь не трогает SQLite.

## Репозиторий и данные

```
PoolNet/
├── hub/src/hub/        FastAPI-ядро, gateway/poolstatus/siteview, pipeline, bot
├── hub/tests/          pytest-набор
├── web/site/           публичный сайт (HTML/CSS/шрифты)
├── pool/src/           TS-движок и публикация
├── pool/workers/api/   edge-API, справочная реализация (не прод)
├── deploy/             systemd/nginx-шаблоны
├── docs/               архитектура, деплой
├── scripts/            site_links.py
└── Makefile            test / lint / site / check
```

В git не попадают: `data/`, `hub/data/`, `pool/data/`, `.state/`, `.work/`,
`.env*`, токены и сессии, `*.key`, `*.pem`, `*.sqlite3`, `*.db`, `*.ndjson`,
локальные бинарники `hub/tools/`. Публикация пула и база VPN создаются на
сервере; `pool/data` в объединённом репозитории — runtime-каталог, а не
коммит. Старый `pool/.github` относится к автономной жизни пакета; активный
CI объединённого репозитория — корневой `.github/workflows`.

## Legacy и совместимость

- `/status` отдаёт файл сайта, если `web/site/status.html` есть; иначе —
  старую страницу `hub` (установка без сайта).
- `/design` и `/mockup` — артефакты проектирования, не продуктовые
  страницы, закрыты `noindex`.
- `/data/*` — 307 на `/pool/*` для старых ссылок и скриптов.
- `pool/workers/api/` сохранён как справочная edge-реализация и не
  участвует в прод-стеке.
- Старый демо-порт `:8931` и демо-сайт пула выведены; редиректы старых
  хостов описаны в `deploy/legacy-redirect.conf.in`.
