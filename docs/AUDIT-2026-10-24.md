# Аудит PoolNet — 2026-10-24

Статус: read-only аудит. Код и прод не изменялись; проверены домен, API,
публикация, админка, 18 страниц RU/EN, тесты и эксплуатация.

Метод: четыре независимых аудита (backend/security, frontend/UX,
data/operations, repo/docs/CI) + ручная перепроверка критичных находок.
Гейты на момент аудита: hub **637 passed / 1 skipped**, pool **118 passed**,
linkcheck **18 страниц**.

## Статус исправлений (2026-10-24)

Исправлено и проверено на проде: SSRF (`is_global`, ведущие нули), лимит
заголовков, не-ASCII токены → 404, cookie-сессия с 12-часовым сроком,
`no-store`, реальный `expire` подписки, xray только для JSON, `/metrics`
закрыт снаружи, `hub.db` 0600 и `UMask=0077`, CI-зависимости/Node 22/ruff pin.
Пул: удалён absolute-form fallback, добавлена nonce-проверка, публикация
требует доказанный exit-IP и исключает IP чекера; старые ложные записи
перепубликованы (27 572 → 5 177, `exit_ip == сервер` = 0, без exit-IP = 0).
Uptime для новых проверок — `null` до 3 успехов, а версия чекера не даёт
наследовать старые 100%. Публикация пишет файлы атомарно и `manifest.json`
с SHA-256; при падении >50% сохраняется предыдущая генерация. Страна считается
по exit-IP. Добавлены ежедневные бэкапы, недельный ретеншн `checks`/событий,
5-минутный healthcheck, restore drill и systemd-hardening пула; старый
`:8444` отвечает 301 на домен. UX: U1–U5, U6 (skip/aria-current), U7 (честный placeholder),
U8, U9, U10, U11, U12, U13, U15, U17, U18; остальные — в PLAN M11.
Гейты после исправлений: hub 648 passed / 1 skipped, pool 127 passed,
linkcheck 18 страниц; Playwright 18 страниц × 2 viewport без ошибок/overflow; тот же smoke-тест
добавлен в CI.

## Краткий итог

Сильные стороны: целостный дизайн, домен и TLS, рабочие бесплатные ключи на
7 дней, понятная админка со сроками/источниками, зелёные тесты, нет ошибок
консоли и горизонтального overflow на проверенных страницах.

Главные проблемы:

1. **P0 — прокси-пул выдаёт не-прокси за «проверенные elite».** В публикации
   33 143 записи; у 13 729 `exit_ip` равен IP самого сервера, у **всех** 33 143
   `uptime_30d = 100`, 27 365 помечены `elite`. В коде есть fallback с
   absolute-form GET (`pool/src/check/stage.ts`), который принимает ответ
   CDN/веб-сервера за работу прокси. Это подрывает главное обещание проекта.
2. **P0 — SSRF в `/api/check`.** `012.0.0.1:80` проходит проверку и резолвится
   в `10.0.0.1` (подтверждено). Публичный эндпоинт может проверять внутренние
   адреса. Нужна строгая проверка через `ipaddress` + `is_global`.
3. **P0 — CI, вероятно, красный.** Hub CI ставит `./hub[dev]`, где нет
   `httpx`/`python-multipart`, нужных тестам; pool CI на Node 20 запускает
   `node --test test/**/*.test.ts`, а glob не раскрывается в `sh`/Node 20.

## План улучшений

### Этап 0 — доверие и безопасность (0–2 дня)

1. Закрыть SSRF: строгий IPv4 + `is_global`, лимит чтения заголовков,
   не-ASCII токены → 404, cookie-сессия с серверным сроком, `no-store`.
2. Исправить проверку прокси: убрать/ограничить absolute-form fallback,
   требовать доказательство форвардинга, отклонять `exit_ip == checker`,
   пересчитать anonymity/uptime; до перепроверки не писать «verified».
3. Атомарная публикация `gen-<id>` + manifest; circuit breaker при падении
   количества >40–50 %.
4. Починить CI (hub deps, Node 22/glob, ruff pin), сделать `make check`
   воспроизводимым.
5. Реальный `subscription-userinfo expire`, закрыть `/metrics`, выдать
   `hub.db` права 0600.

Приёмка: нет SSRF/500; CI зелёный; 0 записей `exit_ip == IP сервера`;
0 записей с uptime 100 без истории; публикация переживает kill -9; free-ключ
показывает реальный срок.
