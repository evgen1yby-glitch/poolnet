# Спецификация проекта: open-proxy-pool

> Документ для мозгового штурма «во что превратить проект». Содержит факты о
> текущем состоянии, конкурентную карту, данные которые собирает только этот
> проект, ограничения и 8 векторов развития с оценкой. Можно передавать
> нейросети целиком как контекст.

---

## 1. Одной строкой

Публичный пул прокси, который **пересобирается каждые 15 минут полностью на
GitHub Actions без единого сервера**: 177 опубликованных списков → разбор →
дедупликация → сквозная проверка каждого кандидата → обогащение (грейд
анонимности, exit IP, задержка, uptime, гео, ASN, флаг TLS-MITM) → публикация
текстовых списков, JSON, country-шардов и статического сайта с поиском,
фильтрами и «плейграундом» проверки любого адреса.

## 3. Что делает проект редким (чем он владеет)

1. **Нулевая инфраструктура.** Все проверки — с GitHub-hosted раннеров, чьи
   IP одноразовы. Операторский адрес никогда не появляется в логах прокси.
   Ни один публичный конкурент этого не делает (monosans проверяет со своего
   сервера).
2. **Греййд анонимности измерением, а не заявлением.** Неизвисимый бенчмарк
   жанра (webscraping.ai, 07.2026) показал: «проверенные» списка дают 0–12%
   живых; заявления источников не коррелируют с реальностью.
3. **Детект устаревания источников.** Дата последнего коммита файла через
   GitHub API; флаг >90 дней. Первый прогон нашёл 9 заброшенных источников в
   собственном реестре.
4. **Данные, которых нет ни у кого в открытом виде:**
   - живучесть по источникам (`aliveBySource` — кто реально поставляет)
   - воронка цикла (3.58M строк → 733k уникальных → ~900 живых)
   - история размера пула (96 точек)
   - флаг TLS-MITM по каждому прокси
   - цепочки (exit IP ≠ прокси)
   - staleDays по источникам
5. **Расширенная метадата как продукт:** latency, uptime-окна, гео, ASN —
   proxifly и monosans отдают `ip:port`.

## 5. Ограничения и слабые места (честно)

- **Пул живёт минуты**: ~900 живых против 733k кандидатов. Для пользователя,
  которому нужна надёжность, бесплатный пул — игрушка (это тоже материал для
  контента и продукта).
- **Нет долгой истории по каждому прокси** — окна uptime копятся в снапшоте.
- **Один сборщик** — pipeline в одном репозитории, нет распределённой сети.
- **Зависимость от GitHub** (Actions, кэш, raw-доставка).
- **Юридическая серая зона** — большинство прокси это неумышленно открытые
  чужие машины. Позиция проекта: дисклеймер, abuse-канал, никакого сканирования.
- **Ключ GFP** — единственный секрет; всё остальное публично.

## 6. Векторы превращения (8 направлений, отсортированы по моей оценке)

### A. «Прокси-обсерватория» — продукт не список, а данные о экосистеме

Публиковать не `ip:port`, а **наблюдения**: полураспад жизни прокси,
распределение по ASN/странам, доля MITM и цепочек, live-rate по источникам,
скорость обновления чужих списков. Форм-фактор: месячный автоматический
отчёт (как HProxy пишет блог вручную, но непрерывно и с raw-данными) +
датасет на HuggingFace. **Уникальность:** в жанре никто не публикует
`aliveBySource` и `staleDays`. Это контентовая машина, которую невозможно
скопировать, не имея того же пайплайна.

### B. «Рейтинговое агентство proxy-листов»

Независимый непрерывный бенчмарк: проект измеряет **другие** proxy-list'ы
(они уже все в реестре!) и публикует таблицу «чей список чего стоит».
Модель как у webscraping.ai, но автоматическая и открытая. **Уникальность:**
становится инфраструктурой оценки жанра, а не участником.

### C. «Oracle API» — SLА для бесплатного

`GET /v1/proxy?country=US&grade=elite&max_latency=800` → JSON с гарантией
«проверен <2 мин назад», отдаётся через Cloudflare Worker с кэшем. Монетизация
опциональна (pro-тир: фильтры, история, вебхуки). **Моат:** нельзя найти
альтернативу с uptime-данными, потому что их никто не собирает в открытом
виде.

### D. «Прокси-генеалогия» — карта цепочек

Мы уже умеем: exit IP ≠ прокси. Развитие: строить граф «кто через кого
ходит» — кластеры перепродажников, скрытые сети, страны-транзитёры.
**Уникальность:** данные о топологии, которых нет ни в одном открытом источнике.

### E. «Распределённая сеть проверки» — протокол вместо репозитория

Сообщество запускает `--node` (контейнер, 5 минут setup), узлы отдают
проверки и получают приоритетный доступ к пулу. **Уникальность:** проект
перестаёт быть репозиторием и становится сетью; ни у кого в жанре такого нет.

### F. «Персональный пул за 1 клик»

Кнопка «Use this template» → у пользователя свой приватный пул, свой домен,
своя телеметрия. Продукт = SaaS-альтернатива бесплатно (self-hosted),
воронка к managed-тиару. **Уникальность:** весь мир продаёт proxy-as-a-service;
это proxy-as-a-repo.

### G. «Журналистика данных о чужих открытых машинах»

Месячный отчёт: сколько в мире открытых прокси, кто они (ASN, страны,
«домашние» vs датацентры), сколько закрылось за месяц. Аудитория — не только
разработчики, но и ИБ/медиа. **Уникальность:** позиция «измерителя
экосистемы», а не «поставщика».

### H. «Архив трендов» — time-machine пула

История `history.json` живёт 96 точек. Развитие: хранить историю по каждому
прокси → анимация «как пул дышал месяцами» на сайте + исследование
(выходные/праздники → всплески открытых прокси). **Уникальность:** сайт как
исследовательский артефакт.

## 7. Мои три фаворита

1. **A (Обсерватория)** — самый дешёвый по усилиям (данные уже собираются),
   максимально далёк от жанра, создаёт контент, который приводит звёзды.
2. **B (Рейтинговое агентство)** — превращает конкурентов в объект
   измерения; естественный PR-двигатель («мы измерили все ваши списки»).
3. **H (Архив трендов)** — единственный визуальный актив, который
   накапливается со временем и не может быть скопирован ретроспективно.

## 8. Ограничения для любого из векторов

- **Юридическое:** все векторы работают только с данными измерений, без
  сканирования; дисклеймер и abuse-канал остаются.
- **Стоимость:** целевой режим — 0 ₽ (Actions free + Pages). C и E допускают
  managed-тир, но база обязана оставаться бесплатной.
- **Репутация:** любой вектор должен повышать честность жанра, иначе теряется
  главный дифференциатор.

## 9. Как читать этот документ нейросети

Задача: предложить превращения проекта, которые (1) невозможно повторить
команде без того же измерительного пайплайна, (2) сохраняют нулевую
инфраструктуру или однозначно её окупают, (3) усиливают честность как
дифференциатор. Оценивай идеи по шкале: новизна в жанре / защищаемость
(moat) / стоимость поддержки / риск репутации. Избегай советов «добавить
больше источников» и «сделать красивше» — это уже сделано и не является
дифференциатором.
