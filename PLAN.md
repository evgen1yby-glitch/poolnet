# evilgate — план объединения двух проектов в один

Объединение **hub** (freevpn: контрольная плоскость VPN-конфигураций, Python) и
**pool** (open-proxy-pool: открытая прокси-база, TypeScript) в единый проект
**evilgate** (evilgate.online) по макету `web/site` (v4: obsidian + aurora).

Итоговая цель: один репозиторий, один сайт, один прод-сервис, обе базы
(прокси HTTP/SOCKS и VPN-конфиги) на одной платформе проверки. Старые
проекты по отдельности после переключения закрываются.

## Структура репозитория

```
evilgate/
├── PLAN.md            ← этот план
├── README.md
├── .gitignore
├── web/site/          ← единый сайт (морф из макета docs/design/evilgate v4:
│                        index / vpn / proxy / verify / premium / status + system.css)
├── hub/               ← контрольная плоскость VPN-пула (Python 3.11, FastAPI, aiogram)
│   ├── src/hub        (api, bot, checker/pipeline 6 этапов, singbox-рендер, store)
│   ├── tests          (pytest-набор ~557 тестов)
│   ├── deploy         (systemd-юниты), scripts, tools (sing-box/xray — только локально)
│   └── LICENSE        AGPL-3.0
└── pool/              ← движок прокси-базы (Node 20, TS, бин: opp)
    ├── src            (sources/parse/check/benchmark/publish/distributed)
    ├── site           (старый сайт-справочник — закрывается, живёт до M3)
    ├── workers/api    (т_unused)
    └── LICENSE        MIT
```

История git старых проектов **не переносится** — свежий независимый репозиторий.

## Этапы

### M1 — боевой веб слой (web + hub-api)
- hub-api раздаёт `web/site` как корень сайта (сейчас макет живёт по /design/...).
- Данные на сайт из двух источников одним шаблоном: VPN-пул — `/api/v1/stats`,
  прокси-пул — `meta.json` + `proxies.json` (данные pool-scripts).
- Живые числа вместо зашитых: в head видно время прогона обеих баз.
- Каналы: pytest 557 passed / ruff clean — gate каждого шага.

### M2 — общая платформа данных
- `pool` публикует в общий каталог (shared data dir), `hub` берёт оттуда
  `meta.json`/`proxies.json` — единый сокет публикации, без дублей кода.
- Единый `GET /api/status.json` на evilgate: поля VPN-пула (funnel/gen/страны)
  + поля прокси-базы (poolTotal/грейды/медиана/цикл) — статус-страница читает
  его один запрос.
- `runId`/отпечаток списка: заполняется реальным значением из pool-прогона.

### M3 — сайт целиком + мотивация ссылок
- Все ссылки: «Открыть пул» → внутренний путь (не :8931), файлы выдачи
  (http/socks4/socks5/country-шарды) публикуются на evilgate.
- Чек-инструмент «проверить любой узел» (structure из proxylist check.html)
  в конфигурации уже собранных данных — отдельной страницей или разделом.
- 404-страница с.Redirects со старых адресов (:8931, :8444/design) → новые пути.
- RU-only copy audit: без сказок, без жаргона; стрелочки «Проверка» и т. п.

### M4 — CI/GitHub
- GitHub Actions: `hub` — pytest + ruff; `pool` — typecheck + eslint + unit;
  сайт — сборка/ссылки-проверка (linkcheck по 6 страницам).
- Секреты: gitleaks в прекоммит + workflow; все ключи только в GitHub Secrets /
  переменных окружения прод-сервера.
- README (публичный): сх.shtml платформы, две базы, методика проверки,
  лицензии (hub — AGPL-3.0, pool — MIT; см. License header docs).
- Локальный git: вкладка к возможности `gh repo create` — решит владелец
  (название/орг/видимость).

### M5 — переключение продакшена
- systemd-юнит evilgate (hub-api): домен evilgate.online, TLS-сертификат.
- Бот (aiogram) остаётся тем же процессом; прокси-планировщик (pool cycle)
  либо cron/таймер на сервере, либо без него — стрижка по результату M2.
- Старые сервисы (freevpn hub-api на :8444, pool демо на :8931) — в режим
  переадресации, затем выключение; каталоги старых проектов — в архив.
- Регистрация домена + DNS + certbot решаются вне репо.

## Правила проекта (обязательные)

1. Реализации строго по макету и ТЗ: не добавлять блоки/функции без явной просьбы.
2. Маркетинг — только RU; тон деловой, без фольклора и прикрас.
3. Все численные факты — только из свежих прогонов обеих баз; без «духреления»
   прошлых значений в копии.
4. Правовая рамка: каталог публичных списков, мы не оператор узлов; трафик
   идёт напрямую клиент → узел.
5. Premium = честный анонс без цен и фейковых Earlier的父亲.
6. Каждый шаг M1–M5 заканчивается verify: pytest/ruff + Playwright-пробы
   сайта (overflow/console) + скриншоты.
